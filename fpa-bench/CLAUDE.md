# FPA_Bench — context for Claude sessions

An FP&A / strategic-finance benchmark for LLMs and agent harnesses. Owner: Seth (personal
project, run on a Claude Max account). Read `NEXT_STEPS.md` first in any new session — it holds
the current roadmap and open decisions. `DESIGN.md` = rationale; `docs/RESEARCH.md` = July 2026
benchmark landscape (why this exists: corporate FP&A is unbenchmarked; harness-as-variable is
the novel axis).

## Commands (run from repo root)

```bash
python -m bench list                  # 12 tasks
python -m bench validate              # pytest: independent solvers re-verify every answer key
python -m bench generate --seed N     # regenerate ALL task data + answer keys
python -m bench show --task <id> --mode chat|agent
python -m bench run --model <spec> --mode chat|agent [--judge <spec>] [--trials N]
python -m bench report                # aggregates results/*.jsonl -> results/REPORT.md
```

Model specs: `anthropic/<id>`, `openai/<id>`, `openrouter/<vendor>/<id>`, `cli/<name>`
(cli names configured in `models.json`). Keys via env: ANTHROPIC_API_KEY / OPENAI_API_KEY /
OPENROUTER_API_KEY. Runner is stdlib-only; pytest is the sole dev dependency.

## Hard rules

1. **Never hand-edit `answer_key.json` or `data/*.csv`.** They are generated by
   `bench/generators.py`. To change a task's numbers, change its generator, rerun
   `python -m bench generate`, then `python -m bench validate`.
2. **Every new task needs an independent solver test** in `tests/test_answer_keys.py` that
   re-derives the key from the CSVs on disk WITHOUT importing generator logic. This is the
   defense against generator bugs. Also assert the task's structural invariant if it has one
   (bridges tie, balance sheet balances, IRR zeroes NPV).
3. **Prompts pin conventions.** Any formula with multiple industry conventions (PVM, NDR,
   payback...) must be spelled out in prompt.md. Grading tests execution, not
   convention-guessing (v0 policy; an "ambiguous conventions" track is a possible v1 addition).
4. **Benchmark integrity in agent mode:** models under test must never see answer keys. The
   runner stages only `data/` into a temp workdir; keep it that way.
5. **Determinism:** generators must use only `random.Random(seed)` — no time, no `hash()`
   (string hashing is per-process randomized; use `zlib.crc32` for stable derived seeds).

## Architecture (one line each)

- `bench/schema.py` — task loading; renders prompts for chat (inline CSV) vs agent (file paths).
- `bench/generators.py` — seeded data + answer-key generation; one `@generator("<task-id>")` per task.
- `bench/graders.py` — JSON extraction from responses, per-field tolerance grading, LLM-judge flow.
- `bench/adapters.py` — Anthropic API, OpenAI-compatible (incl. OpenRouter), CLI harness subprocess.
- `bench/runner.py` — runs tasks × trials, stages agent workdirs, writes results/*.jsonl.
- `bench/report.py` — leaderboard + hardest-tasks tables.
- `tasks/<id>/` — task.json (grading spec), prompt.md, data/, answer_key.json.

## Adding a task (checklist)

1. `tasks/<id>/task.json` + `prompt.md` (with `{data}` placeholder and explicit conventions).
2. Generator function in `bench/generators.py` — compute the key from data AS WRITTEN (post-rounding).
3. Independent solver test in `tests/test_answer_keys.py`.
4. `python -m bench generate && python -m bench validate`.
